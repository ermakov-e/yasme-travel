# Тестирование

## Текущее состояние

В проекте **нет настроенного тестового раннера**: отсутствуют `test`-скрипт, конфигурация Vitest/Jest и тестовые файлы. Это осознанное состояние MVP, а не ошибка.

Проверки, которые доступны сейчас:

| Проверка | Команда |
|---|---|
| Типы | `npx tsc --noEmit` |
| Линтер | `pnpm lint` |
| Документация и архитектура | `pnpm docs:check` |
| Ручной сценарий | `pnpm dev` |

## Предлагаемая настройка

Раздел описывает **предложение**, а не действующее требование. Установка зависимостей и изменение `package.json` выполняются только после согласования.

Рекомендуемый стек:

- **Vitest** — раннер, совместим с Vite.
- **@testing-library/react** + **jsdom** — компонентные тесты.
- **msw/node** — те же обработчики, что и в браузере.
- **@testing-library/user-event** — пользовательские сценарии.

Что тестировать в первую очередь:

| Область | Что проверять |
|---|---|
| `authSlice` | `login` создаёт пользователя, `logout` очищает состояние |
| `AuthGuard` / `GuestGuard` | редиректы при разных состояниях |
| `createGroupSchema` | обязательные поля, минимальная длина, адрес |
| `CreateGroupModal` | переходы между шагами, блокировка кнопки, сабмит |
| `GroupsPage` | loading / error / empty |
| MSW-контракты | совпадение типов запроса и ответа |

## Связь со спеками

- В frontmatter спеки есть поле `tests` — список путей к тестам.
- Если тестовый раннер появится, поле заполняется путями; `docs:check` проверит их существование.
- Пока раннера нет, поле остаётся пустым; это допустимо для статусов `draft`, `approved` и `done`.

## Правило Definition of Done

Пока раннер не настроен, обязательны `tsc`, `lint` и ручная проверка сценариев приёмки из спеки. После настройки — тесты становятся обязательными для изменений логики.
