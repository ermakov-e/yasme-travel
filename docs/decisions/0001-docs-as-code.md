# 0001 — Документация как код: спеки + генерация

- Статус: принято
- Дата: 2026-11-22

## Контекст

Проект развивается с участием агентов. Требования живут в чатах и трекере, архитектура — в голове и частично в `AGENTS.md`. Документация быстро устаревает: `AGENTS.md` уже ссылался на несуществующие `docs/architecture.md` и `docs/state-management.md`.

Нужен контур, в котором:

- каждая задача имеет проверяемые требования;
- документация о фактическом состоянии кода не требует ручной синхронизации;
- агент понимает, что читать и что обновлять.

## Решение

1. **Спека на каждую задачу** — `docs/specs/<area>/<NNN>-<slug>.md` с frontmatter и обязательными секциями.
2. **Автогенерация** — `scripts/docs/generate.mjs` строит `docs/generated/*` из `router.tsx`, `*Slice.ts`, `*apiSlice.ts`, `shared/ui`, `entities`, MSW-обработчиков и frontmatter спек.
3. **Гейт** — `docs:check` падает, если generated устарел, спека невалидна, ссылка битая или маркер `@spec` не резолвится.
4. **Ручные документы** — только там, где знание нельзя вывести из кода: архитектура, правила, ADR, глоссарий.

## Последствия

- Появляется обязанность обновлять спеку и запускать генерацию.
- Любая ручная правка `docs/generated` будет перезаписана.
- Документация становится проверяемой в CI.
- Скрипты не зависят от `node_modules` — работают на чистом Node.

## Альтернативы

- **Только ручная документация** — отвергнуто: устаревает и расходится с кодом.
- **Только автогенерация** — отвергнуто: не выражает требования и решения.
- **Storybook / doc-генератор из JSDoc** — избыточно для MVP, не покрывает требования задач.
