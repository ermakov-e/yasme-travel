# 0002 — Проверка границ FSD скриптом

- Статус: принято
- Дата: 2026-11-22

## Контекст

Правила FSD описаны в [fsd.md](../fsd.md), но нарушения уже есть: `shared` импортирует `features`, `features/ui` импортирует `widgets`, `shared/ui/modal` импортирует тему из `app`. Ревью не масштабируется и не ловит type-only импорты.

## Решение

Сканер `scripts/docs/scanners/architecture.mjs`:

- разбирает импорты в `src`;
- определяет слой файла и цели;
- сравнивает ранги слоёв;
- группирует нарушения по файлу и направлению;
- пишет отчёт в [generated/architecture-check.md](../generated/architecture-check.md).

Правила:

- импорт значения снизу вверх — `error`;
- type-only импорт снизу вверх — `warning`;
- `@app/hooks` — прагма;
- type-only импорт `RootState` из `app` — прагма.

На текущем этапе `docs:check` валит только `error`; с `--strict` — и `warning`.

## Последствия

- Нарушения видны в документации и в выводе проверки.
- Появляется стимул исправлять долги ([platform/003](../specs/platform/003-fsd-cleanup.md)).
- Проверка эвристическая (регулярные выражения + балансировка скобок), но покрывает текущий код и падает громко при неразобранной структуре router/store.

## Альтернативы

- **ESLint-правило `import/no-restricted-paths`** — точнее, но требует настройки зон под алиасы и не строит отчёт для документации. Возможный следующий шаг.
- **Только ревью** — отвергнуто: пропускает нарушения.
