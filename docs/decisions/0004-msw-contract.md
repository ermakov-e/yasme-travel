# 0004 — MSW как dev-контракт API

- Статус: принято
- Дата: 2026-11-22

## Контекст

Бэкенд для MVP отсутствует. Нужен способ разрабатывать UI и проверять контракты без внешнего сервера, сохраняя возможность позже переключиться на реальный API.

## Решение

- MSW включается только в dev (`src/main.tsx`, `import.meta.env.DEV`).
- Обработчики лежат в `src/shared/mocks/handlers` и повторяют контракты из `entities` и `features`.
- `onUnhandledRequest: "bypass"` — запросы, которых нет в моках (например, Яндекс-геокодер), уходят в сеть.
- Данные моков живут в памяти и сбрасываются при перезагрузке.
- В production моки не стартуют; базовый URL берётся из `VITE_API_BASE_URL` (по умолчанию `/api`).

## Последствия

- UI можно разрабатывать без бэкенда.
- Контракт мока нужно синхронизировать с типами вручную; расхождение ловится ревью и спеками.
- Тесты в будущем смогут переиспользовать те же обработчики через `msw/node`.
- Мок-типы создают отклонения слоёв: `shared/mocks` импортирует типы из `features` и `entities` (type-only). Это зафиксировано в проверке архитектуры.

## Альтернативы

- **json-server** — отдельный процесс, сложнее в браузере и тестах.
- **Хардкод данных в компонентах** — отвергнуто: не имитирует сеть и не переиспользуется.
- **Реальный бэкенд** — недоступен на этапе MVP.
