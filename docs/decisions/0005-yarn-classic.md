# 0005 — Yarn Classic как пакетный менеджер

- Статус: принято
- Дата: 2026-11-25

## Контекст

Проект начинался на pnpm 10. Принято решение перейти на Yarn, чтобы все команды проекта вызывались через него. Yarn 1.22 уже установлен в окружении разработчика.

## Решение

- Пакетный менеджер — Yarn 1 (Classic), `packageManager: yarn@1.22.22` в `package.json`.
- Lock-файл — `yarn.lock`, `pnpm-lock.yaml` удалён.
- Зависимости ставятся в `node_modules` (без PnP), поэтому Vite, ESLint и TypeScript работают без доп. настройки.
- Команды в документации: `yarn <script>`; аргументы скриптам передаются без `--` (`yarn docs:check --strict`).

## Последствия

- Все команды в README, AGENTS.md, `docs/` и в выводе `scripts/docs/` используют `yarn`.
- При переходе lock-файл собран заново, поэтому версии транзитивных зависимостей могли сдвинуться в пределах диапазонов из `package.json`.
- Yarn 1 больше не развивается (только исправления безопасности). Переход на Yarn 4 потребует `.yarnrc.yml` (`nodeLinker: node-modules`) и нового ADR.

## Альтернативы

- **Оставить pnpm** — отвергнуто решением владельца проекта.
- **Yarn 4 + node_modules** — актуальная ветка, но требует corepack и доп. конфигурации; отложено.
- **Yarn 4 + PnP** — нужна настройка IDE/TypeScript (sdks), избыточно для MVP.
