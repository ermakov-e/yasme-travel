# auth-002 — Сохранение сессии

## Контекст

`AGENTS.md` требует, чтобы при загрузке приложение проверяло `localStorage` и восстанавливало сессию. Сейчас `authSlice` стартует с `isAuthenticated: false`, поэтому перезагрузка страницы разлогинивает пользователя. При этом `shared/api/apiSlice.ts` уже пытается читать `token` из `localStorage`, но никто его не записывает.

## Требования

- После успешного входа данные сессии сохраняются в `localStorage`.
- При старте приложение восстанавливает сессию из `localStorage` до первого рендера защищённых маршрутов.
- Выход очищает сохранённую сессию.
- Повреждённые или устаревшие данные не ломают приложение: сессия считается отсутствующей.
- Гварды используют восстановленное состояние, без «мигания» `/auth`.

## Сценарии приёмки

1. Войти → перезагрузить страницу → остаться на `/groups`.
2. Выйти → перезагрузить страницу → оказаться на `/auth`.
3. Записать в `localStorage` невалидный JSON → приложение открывает `/auth` без падения.
4. Открыть приложение в новой вкладке → сессия восстановлена.

## FSD

- `features/auth` — восстановление и очистка состояния.
- `shared/lib` — безопасный доступ к `localStorage`.
- `app/store` или bootstrap в `main.tsx` — инициализация до рендера.

## Файлы

Существующие: `authSlice.ts`, `store.ts`, `main.tsx`, `apiSlice.ts`. Плановый модуль хранилища: `src/shared/lib/storage.ts`.

## Данные и контракты

- Ключ хранения: `auth` (пользователь) и `token` (для API).
- Формат: JSON с версией схемы.
- При несовпадении версии данные удаляются.
