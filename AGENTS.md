# AGENTS.md

## Project Overview

Yasme Travel — frontend приложение для совместной работы с картой.

Пользователи:

- создают группы (привязанные к геолокации)
- добавляют фотографии в группы
- просматривают группы на карте

Логика:

- каждая группа привязана к геолокации (lat, lng, address?)
- группа содержит коллекцию фотографий
- карта — отдельный экран с отображением групп как точек

Стек:

- React
- TypeScript
- Vite
- Redux Toolkit
- MUI
- styled-components
- React Router

Архитектура:

- Feature-Sliced Design (FSD)

## Development Workflow

Перед реализацией задачи ОБЯЗАТЕЛЬНО:

1. Проанализировать задачу
2. Найти или создать спеку в `docs/specs` (`yarn spec:new <area> "Название"`)
3. Определить слой (FSD) и зафиксировать его в спеке
4. Согласовать требования и сценарии приёмки (`status: approved`)
5. Предложить структуру файлов (`files` / `planned` в спеке)
6. Только после этого писать код
7. Прогнать гейты: `npx tsc --noEmit`, `yarn lint`, `yarn docs`, `yarn docs:check`
8. Перевести спеку в `done` и закоммитить вместе с generated

Подробный процесс: `docs/agent/workflow.md`.
Чек-лист готовности: `docs/agent/definition-of-done.md`.

## Authentication (MVP)

Используется mock авторизация:

- login + password
- данные не проверяются (мок): подходит любой непустой логин и пароль
- состояние хранится в Redux
- localStorage пока не используется; сохранение сессии запланировано в `docs/specs/auth/002-session-persistence.md`

Поведение:

- после логина → доступ к приложению
- при перезагрузке сессия теряется (текущее состояние MVP)
- если не авторизован → /auth

## Documentation System

Источники истины:

- **Требования** — `docs/specs/<area>/<NNN>-<slug>.md`
- **Фактическое состояние кода** — `docs/generated/*` (генерируется скриптом)
- **Решения** — `docs/decisions/*` (ADR)
- **Процесс агента** — `docs/agent/*`

Правила:

- Нет спеки — нет реализации. Исключение: опечатки и правка документации.
- Спека создаётся через `yarn spec:new` и содержит frontmatter: `id`, `title`, `status`, `layer`, `areas`, `files`, `planned`, `tests`, `created`, `updated`.
- Первичный файл реализации помечается комментарием `// @spec <id>`.
- `docs/generated` обновляется только командой `yarn docs`.
- Перед коммитом обязателен `yarn docs:check`.
- Архитектурное решение фиксируется в ADR, а не только в переписке.
- Нарушения слоёв и покрытие спеками видны в `docs/generated/architecture-check.md`.
